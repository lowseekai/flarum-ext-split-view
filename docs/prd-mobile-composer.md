# Split View 移动端全屏编辑与预览切换 PRD

## 文档信息

- 状态：待评审
- 日期：2026-10-05
- 所属项目：`nodeloc/flarum-ext-split-view`

## 背景

手机上打开 Flarum 发帖编辑器并弹出软键盘后，正文可编辑区域显得较矮，编辑器上下还会留下较多无效空间。启用 Split View 预览时，正文和预览同时分配有限的垂直空间，进一步压缩输入区域。Discourse 的移动端编辑体验提供了参考：编辑器使用几乎整个可视屏幕，正文填满标题、选项和工具栏之外的剩余空间。

## 目标

1. 手机上编辑时，让 Composer 使用扣除浏览器可视区域限制后的最大可用高度。
2. 标题、发帖选项和工具栏保持可用，正文编辑区弹性填满其余空间。
3. 移动端正文编辑和实时预览互斥显示，避免二者同时争用高度。
4. 通过现有预览按钮在编辑与预览视图间切换，并保留已输入的草稿和光标状态。
5. 桌面端现有并排预览行为保持不变。

## 非目标

- 不重新设计 Flarum 的发帖流程、标题栏、标签或权限控件。
- 不改变 Markdown 渲染、预览内容或发帖提交逻辑。
- 不新增独立扩展或额外配置项。
- 不在本次范围内修复与 Composer 布局无关的插件问题。

## 用户与场景

移动端论坛用户在 Safari 或 Chrome 中发帖、回复主题。用户打开 Composer 后开始输入；需要检查 Markdown 效果时打开预览；检查完成后返回编辑，继续输入并发布。

## 功能需求

### 移动端全屏 Composer

- 在移动断点下，Composer 应覆盖页面主要可视区域，避免保持桌面式居中小面板或底部窄面板。
- Composer 高度应跟随浏览器的可视视口变化，兼容软键盘弹出、收起及地址栏伸缩。
- 布局应考虑设备安全区。顶部关闭/标题/提交操作、标题输入、发帖选项和编辑工具栏应保持可见或可访问。
- 正文区域应使用剩余高度，并允许正文内容在区域内部滚动；不得通过固定像素高度限制正文。
- 键盘出现时，页面内容不应盖住编辑工具栏；不应产生 Composer 外层与正文区相互抢滚动的情况。

### 编辑与预览互斥切换

- 手机端进入 Composer 时默认显示编辑视图。
- 点击现有预览按钮后显示预览视图，并隐藏正文输入区以释放空间；预览内容使用可用区域。
- 再次点击同一按钮返回编辑视图，恢复草稿内容和合理的光标位置。
- 预览切换不得清空输入、重置标题/标签/其他 Composer 状态，或意外提交讨论。
- 预览状态视觉上应与现有按钮状态一致；键盘在切换到预览时可由浏览器自然收起，返回编辑时允许用户重新聚焦输入区。
- 若正文为空，预览视图应显示可理解的空状态，不应表现为大片无标识空白区域。

### 桌面端兼容

- 桌面端保持当前 Split View 并排编辑与预览布局、现有预览切换逻辑和 Composer 行为。
- 移动端新增布局不得改变桌面端高度分配。

## 验收标准

1. iPhone Safari 真机上打开新建讨论 Composer，弹出键盘后 Composer 使用可视区域，正文从工具栏下方延伸到键盘上方的可用空间。
2. 软键盘弹出、收起以及 Safari 地址栏展开/收起时，正文与工具栏没有重叠、裁切或明显空洞，布局不会持续抖动。
3. 编辑视图与预览视图每种状态下只有当前视图占用主要正文区域；反复切换至少 10 次，工具栏、标题和正文仍可用。
4. 输入多段文本后切换到预览再返回，文本完整保留，光标/选择位置尽可能保留，且可以立即继续输入。
5. 普通正文、空正文、付费正文及已接入的其他编辑器模式不会使 Composer 超出可视区域或隐藏工具栏。
6. 桌面视口下回归验证并排预览正常，发布流程不受影响。
7. Android Chrome 至少完成一次键盘弹出/收起验证；在没有对应真机时，需明确标注未覆盖的平台。

## 验证方式

- 使用真实 iPhone Safari 和软键盘验证视口变化；桌面设备模拟器只能作为布局回归，不能替代真机键盘验收。
- 在浏览器中测量 Composer、正文区、工具栏相对可视视口的位置，确认无溢出和遮挡。
- 自动化回归覆盖视口尺寸变化、编辑/预览反复切换、草稿保留，以及桌面并排模式。
- 发布前在测试草稿中验证，不提交测试讨论。

## 实施约束与风险

- Flarum Composer、Split View 及其他编辑器扩展都可能参与高度分配；实现前需确认实际 DOM 和运行时布局归属，避免多个元素同时承担弹性高度。
- iOS Safari 软键盘会改变 Visual Viewport，且地址栏会动态伸缩。只使用静态 `100vh` 可能导致键盘遮挡或底部空隙，需以真机表现验收。
- 其他扩展注入的正文编辑器（例如付费内容编辑器）必须保持可见状态与预览切换同步。
- 若现有预览按钮在 Flarum Core 或其他扩展中有额外语义，实施前需通过线上 DOM 和状态行为确认，不应仅按按钮样式推断。

## 发布判定

所有验收标准通过后才发布。若真机键盘场景仍出现工具栏遮挡、正文无法获得剩余高度、预览切换丢失草稿或桌面布局回归，则不发布。
